# Accounts and security

- **A1** People sign in with their **mossyleaf account** (`accounts.mossyleaf.studio`, shared by every mossyleaf app). There is no sign-up, password or invitation in Mossy Meals: accounts are invited, reset their password and manage passkeys in mossyleaf accounts, and only members of its `mossy-meals` group may open the app (others see "Your mossyleaf account does not have access to Mossy Meals yet."). — `OidcSingleSignOn`, `AccountsAuthenticator`
- **A1b** On sign-in the account (OIDC `sub`) is matched to its user; otherwise the first sign-in creates the user, named after the account (`name`, then `preferred_username`, then the part of the email before @). A later email change in the account follows on the next sign-in. An email already used by another user is refused, and an account without an email cannot join. The time zone is not stored: the device sends the day it means. — `SignInHandler`
- **A2** Signing out of Mossy Meals also ends the mossyleaf accounts session, then comes back to Mossy Meals (which asks to sign in again); a session restored by remember-me has no ID token to show mossyleaf accounts, so it ends on the mossyleaf accounts page instead. A sign-in link (`state` + PKCE verifier) works once, for the browser that started it. — `SignOutOfAccounts`, `AccountsSession`, `SignInAttempts`
- **A3** There is **one shared kitchen**: every signed-in user, that is every member of the `mossy-meals` group, sees and edits everything. There is no household and no owner scoping. A person shows up among the **members** after their first sign-in; the members (everyone, ordered by display name ignoring case) travel with the page in the `members` list of the session block, as `{id, name}`. — `KitchenMembers`
- **A4** The language is the `locale` cookie when it holds `en` or `fr`, otherwise the best match of the browser's `Accept-Language`, otherwise English. It is not an account setting. — `LocaleListener`
- **A5** Every page and API response answers with security headers: a content security policy (`default-src 'self'`, no inline script or style, no external host, `form-action` limited to the app and the accounts origin; not sent in `dev`, where Vite needs inline code), `Strict-Transport-Security` over HTTPS, `X-Content-Type-Options: nosniff`, `Referrer-Policy: same-origin`, a `Permissions-Policy` that turns camera, microphone, geolocation, payment and USB off, `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy: same-origin`, and `X-Frame-Options: DENY`. — `SecurityHeaders`
- **A6** The app is not discoverable: `robots.txt` disallows everything, every page carries `<meta name="robots" content="noindex, nofollow">` and every response `X-Robots-Tag: noindex, nofollow, noarchive`. The production host name is never committed (the repository is public): it only lives in the server `.env`, the proxy configuration, the accounts server and the Android build's `local.properties`. — `SecurityHeaders`, `public/robots.txt`
- **A7** Sign-in requests are rate limited per client address: `/login` and `/login/check` share a sliding window of `LOGIN_RATE_LIMIT` requests (30) every 15 minutes. Beyond it the visitor gets the sign-in page with a "too many attempts" message, status 429 and a `Retry-After` header. — `LoginRateLimit`
- **A8** The API refuses writes that come from another site (403): the browser's `Sec-Fetch-Site` must be `same-origin` or `none`, or, without it, any `Origin` header must be the app's own. Encoded API paths are decoded before the check. Reads are left to the session cookie (SameSite=Lax). — `SameOriginGuard`
- **A9** The session lives in PostgreSQL and the remember-me cookie keeps phones signed in for 30 days. A signed-out API call answers 401 (the SPA then goes to `/login`), a signed-out page redirects to `/login`. — `AuthenticationEntryPoint`
